# Documentation map

Use this file as the first stop when you need to understand where information lives in the project documentation.

## Where to look

| File | Use it for |
|---|---|
| `AI_RULES.md` | Central rulebook for AI work, development standards, mandatory habits, and cross-document rules. |
| `ARCHITECTURE.md` | System architecture, folder structure, data flow, major components, and how the app is organized. |
| `CODESTYLE.md` | Swift code style, formatting, naming, and implementation conventions. |
| `DESIGN.MD` | Visual design system, colors, typography, spacing, components, and UI rules. |
| `GIT_WORKFLOW.md` | Branching, commits, PR/iteration habits, and Git process guidance. |
| `CHANGELOG.md` | Version history and past changes. |
| `ROADMAP.md` | Planned features, future direction, and long-term product goals. |

## AI navigation rule

Before searching through documentation manually:

1. Open `AI_RULES.md` first for mandatory project rules.
2. Open this file next to choose the correct document.
3. Then go directly to the relevant file instead of scanning the whole folder.

## Maintenance rule

If a new documentation file is added, update this map in the same iteration.
If the purpose of an existing file changes, update this table immediately so future AI agents do not need to rediscover the structure.
